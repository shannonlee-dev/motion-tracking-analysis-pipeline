# 수동 확인 및 한계 분석 기록


## 추적 측정

20~30초 영상을 사용하고, 두 객체 겹침 영상을 최소 1개 포함한다.
영상명·설정·관찰 구간을 기록한다. 아래 기록 행을 이벤트마다 복사해 작성한다.
프레임 번호는 앱 표시 기준으로 0부터 시작하며 범위 양끝을 포함한다.

- ID Switch: 겹침 이후 이전과 다른 ID가 5프레임 이상 연속 유지될 때 센다.
- 추적 실패: 대상이 화면에 있지만 10프레임 이상 연속 미검출 또는 ID 미부여인 구간당 1회 센다.
- 50% 이상 가려진 구간은 추적 실패에서 제외하고 관찰 메모에 남긴다.
- 실패율: 실패가 한 번 이상 발생한 이벤트 수 / 관찰 이벤트 수 × 100.
- 겹침 외 조건의 ID 변경은 메모에 별도로 기록한다. 미측정은 빈칸으로 두며 0으로 쓰지 않는다.
- 5·10프레임 기준은 저장 영상을 프레임 단위로 확인할 수 있는 플레이어에서 점검한다.

## 특징점 매칭

같은 등록 물체로 조건을 바꾸어 기록한다. 회전이 평면 내 회전인지 촬영 시점 변화인지 명시한다.
추출 수는 장면 특징점 수, 매칭률은 매칭 수 / 등록 이미지 특징점 수 × 100으로 기록한다.
등록 이미지·등록 특징점 수·사용 설정을 함께 적는다.
앱 내부의 `TargetMatcher.target_kp`와 `MatchResult.keypoints`, `matches`에서 개수를 확인할 수 있다.
현재 화면에는 개수가 표시되지 않으므로 관찰 시 디버거 등으로 값을 확인한다.

| 조건 | 추출된 특징점 수 | 매칭된 특징점 수 | 매칭률 | 인식 여부·메모 |
| --- | --- | --- | --- | --- |
| 정면 | | | | |
| 30도 회전 | | | | |
| 60도 회전 | | | | |
| 30% 가림 | | | | |
| 50% 가림 | | | | |

## 배경 모델링과 추적 규칙 비교

같은 영상에 학습률을 최소 3가지 적용한다. 예: `--learning-rate 0.001`, `0.01`, `0.1`.
각 실행은 처음부터 시작하고 다른 설정은 고정한다.

| 학습률 | 느린 이동·정지 시 관찰 | 조명 급변 시 관찰 | 근거 프레임·캡처 |
| --- | --- | --- | --- |
| 0.001 | | | |
| 0.01 | | | |
| 0.1 | | | |

거리 제한(`--max-distance`) 또는 속도 예측(`--predict-velocity`)을 바꿔 겹침 구간을 비교한다.

## 한계 분석

관찰한 영상·프레임·수치를 근거로 작성한다.

- 배경 학습률이 느린 변화와 빠른 변화에 어떻게 영향을 주었는가?
- 겹침에서 거리 기반 추적이 실패한 이유와 규칙 변경의 효과는 무엇인가?
- 위치만으로 객체를 구분할 수 없는 사례가 있었는가?
- ORB/SIFT 같은 특징점 방식은 회전·가림에서 어떤 한계를 보였는가?
- 객체 외형·다양한 변형·환경 변화를 학습하면 어떤 개선을 기대할 수 있는가?

측정 환경: Python·OpenCV 버전, 장치, 영상 FPS, 앱 설정을 작성한다.
