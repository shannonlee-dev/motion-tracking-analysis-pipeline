# 동작 추적·ORB 인식 실험 보고서

측정일: 2026-09-18–19. 기준 코드: 로컬 `main`의 `a48a5515d2dd94ec442d9d02f2495f541dac5b84`.
`motion_tracking/`의 앱 구현과 설정은 변경하지 않았다. 원격 main의 최신 여부를 별도로 확인한 결과는 아니다.

**제출 상태: 특징점·학습률 실험과 분석은 재현 완료. 추적 표는 가림·객체 대응 확인이 남은 잠정 결과이며, 과제 전체의 최종 충족을 선언하지 않는다.**
30개 관찰창과 집계 근거를 확보했지만, IoU 기반 자동 대조를 사람이 확정한 사건 기록으로 가장하지 않는다.
특히 bbox 겹침률은 실제 신체의 가림률이 아니며, 가림 후보를 두 객체 모두에 적용한 보수적 제외는 최종 규칙을 완전히 검증한 것이 아니다.

## 1. 측정 환경과 설정

Python 3.12.3, OpenCV 4.13.0, NumPy 2.4.3, Linux/WSL2 x86_64, CPU 처리, OpenCV 스레드 1, RNG seed 0.
입력·등록 이미지 SHA-256과 환경은 [environment.json](../results/tracker/baseline/submission/environment.json)에 기록했다.
이 문서의 측정은 리팩토링 이전에 실행한 baseline이다. 기존 수치·해석을 보존하며 새 실행은 results/<목적>/runs에 별도로 기록한다. 기존 `results/tracker/baseline/case_01`–`results/tracker/baseline/case_19`와 과거 커밋의 추적 성공·실패 집계는 사용하지 않았다.

## 2. 추적 측정 방법과 한계

- ID Switch는 겹침 전 5프레임 이상 확인된 ID와 겹침 후 다른 ID가 5프레임 연속 유지될 때 센다. 이후 관찰창의 추가 확정 변경도 세며, 재발급(fragmentation)을 포함한다. 겹침 외 ID 변화는 이 지표에 포함하지 않는다.
- 추적 실패는 대상이 존재하는데 ID가 대응되지 않는 **10프레임 이상 연속 구간당 1회**다. 한 사건에 여러 실패가 가능하다.
- 실패율은 **실패가 1회 이상인 사건 수 / 조건별 사건 수 ×100**이다. 실패 구간 수를 분자로 쓰지 않는다. ID Switch만 발생한 사건은 이 실패율의 분자가 아니다.
- 가림 제외 프레임은 누락·새 ID 확정의 연속성을 끊지만, 마지막으로 확정된 ID는 보존한다. warmup과 GT 부재 프레임도 제외한다.

현재 자동 대조는 매 프레임 전체 GT와 현재 관측 트랙(`missing==0`) 사이 IoU를 큰 순서로 일대일 할당하고 IoU ≥0.1만 대응으로 인정한다.
이는 **평가용 대응 규칙**이며 앱의 추적 규칙을 바꾸지 않는다. 한 bbox가 두 사람을 동시에 검출한 것으로 집계되지 않는다.
그러나 실제 사람 일부에 작은 bbox/ID가 붙어도 IoU <0.1이면 자동 대조는 누락으로 볼 수 있다. 반대로 배경 검출이 GT와 겹칠 수 있다.
따라서 아래 값은 사람의 존재·ID를 매 프레임 최종 판정한 수동 정답과 구분해야 한다.

CAVIAR 01–03 주석은 로컬에 남아 있던 XML을 복구해 데이터셋 이름과 영상의 위치 대응을 점검했다.
04–11은 현재 출처 manifest의 XML과 원본 시작 프레임을 적용했다. 15–19는 LASIESTA 빨강 전경·흰색 일시 정지 라벨에서 bbox를 얻었다.
14는 직접 관찰한 bbox 기준점 사이 선형 보간이며 공식 GT가 아니다.
[주석 출처](../data/tracker/reference/annotation_sources.json), [보존된 평가 bbox](../data/tracker/reference/ground_truth.json),
[14번 기준점](../data/tracker/reference/annotations/14_anchors.json)에 구분했다.

**미확정 부분:** 04–11의 가림 제외 범위는 GT 박스 중첩과 대표 프레임 관찰로 정한 후보다. 실제 신체 50% 이상 여부·대상별 경계를 확정하지 않았다.
특히 두 객체 모두를 제외하는 방식은 앞쪽의 보이는 객체까지 빼서 실패를 적게 셀 수 있다.
원본 영상과 아래 리뷰 이미지를 이용해 대상별 제외를 확정해야 제출용 추적 최종값이 된다.

## 7. 배경 모델링의 한계와 수학적 원리

한 픽셀 위치 x의 시간 t 색 벡터를 I_t(x)라고 하면 혼합 모델의 개념은 다음과 같다.

$$p(I_t(x))=\sum_{k=1}^{K} w_{k,t}(x)\,\mathcal N(I_t(x);\mu_{k,t}(x),\Sigma_{k,t}(x)),\quad \sum_k w_{k,t}(x)=1.$$

반복적으로 관측되는 픽셀 값에 대응하는 성분들이 배경을 이루며, 현재 관측이 배경 성분과 충분히 일치하지 않으면 전경 후보가 된다.
개념적인 성분 일치 기준은 정규화 거리
$$D_k^2=(I_t-\mu_k)^\top\Sigma_k^{-1}(I_t-\mu_k)$$
이며, 현재 구현은 OpenCV MOG2의 분산 임계값을 16으로 둔다. 이는 RGB 차이 16이라는 뜻이 아니다.
MOG2는 적응적 Gaussian mixture이므로 단일 평균 영상과의 차분만 수행하는 방식보다 반복적 배경 변동을 표현할 수 있다.
[OpenCV MOG2 공식 API](https://docs.opencv.org/4.x/d7/d7b/classcv_1_1BackgroundSubtractorMOG2.html)를 참조했다.

학습률 α의 효과는 개념적으로 가중치 갱신 `w ← (1−α)w + α·일치여부` 및 일치 성분 평균의 새 관측 반영으로 이해할 수 있다.
이 식은 학습률의 역할을 설명하는 축약 모델이며 OpenCV의 성분 생성·정리·평균/분산 갱신 전체를 그대로 옮긴 구현식은 아니다.
작은 α는 기존 배경을 오래 기억하고, 큰 α는 현재 관측을 빨리 배경으로 받아들인다.
17번의 정지 전경 보존과 조명 오검출 사이의 수치 차이가 이 trade-off를 보여 준다.

조명 급변은 수많은 픽셀의 관측 분포를 동시에 이동시키므로 기존 배경과 불일치하여 넓은 false positive를 만든다.
17번 0.001의 f240 마스크가 이에 해당한다. 그림자도 새 객체 없이 밝기를 바꾸므로 색/밝기만으로 객체와 구분하기 어렵다.
현재 `motion.py`의 MOG2 처리는 그림자 라벨 127을 threshold 200으로 제거한다. 원시 라벨이 그림자로 분류된 사람 픽셀까지 제거될 수 있으며,
뒤의 open/close와 contour 면적 필터가 이미 소실된 객체를 복원하지 못한다.

배경/전경 분리는 의미적 객체 검출과 다르다. 빨간 문 앞의 S03에서는 사람이 계속 존재해도 정지 후 전경이 사라진다.
반대로 17번에서 변한 창·벽은 사람이 아니어도 전경으로 나타난다. 모델의 초기화와 지속 갱신이라는 구조는
[OpenCV 배경 차분 설명](https://docs.opencv.org/4.x/d1/dc5/tutorial_background_subtraction.html)과 연결된다.

## 8. 거리 기반 추적의 본질적 한계

`tracker.py`는 bbox 중심 사이 모든 거리 행렬을 만들고 전체 쌍을 가까운 순서로 stable sort하여
아직 사용하지 않은 기존 트랙과 검출을 하나씩 연결하는 greedy matching이다. 전역 비용을 최적화하는 Hungarian 배정이나 외형 비교가 아니다.
max_distance보다 먼 쌍은 연결하지 않는다. 연결되지 않은 트랙은 missing을 증가시키고 **max_missing 초과** 시 삭제하며 새 검출에는 새 ID를 부여한다.
속도 예측을 켜면 마지막 중심에 `velocity × (missing+1)`을 더한 위치를 사용한다.

두 사람이 가까워지면 잘못된 대상의 중심이 더 가까울 수 있고, 전경이 한 contour로 합쳐지면 두 사람에 대응할 관측 자체가 하나만 남는다.
다시 분리될 때 이전 중심만으로 어느 사람이 누구인지 복원하기 어렵다.
O01에서는 기존 ID 2가 f209–213에 ID 6으로, 기존 ID 4가 f228–232에 ID 6으로 대응되는 자동 대조 결과가 나왔다.
이는 같은 ID가 시점에 따라 다른 사람에 대응하는 실패 후보이며, 단순히 ID가 화면에 남아 있다는 것으로 정체성 유지를 보장할 수 없다.

같은 검출 bbox를 유지하고 규칙 하나씩만 바꿨다. 아래는 동일한 미확정 가림·대응 규칙을 적용한 비교다.

| 추적 규칙 | 겹침 후 ID Switch | 겹침 추적 실패 | 겹침 실패율 |
| --- | --- | --- | --- |
| 기본 거리50 / missing15 / 예측OFF | 15 | 39 | 100.0% |
| 거리80만 변경 | 17 | 39 | 100.0% |
| missing30만 변경 | 14 | 39 | 100.0% |
| 속도 예측ON만 변경 | 15 | 39 | 100.0% |

거리 완화는 ID 변경 후보를 15→17로 늘렸다. missing 연장은 15→14로 일부 감소시켰지만 관측 누락 39구간은 그대로다.
미관측 트랙을 내부에 더 오래 보관해도 검출·ID 부여 성공으로 세지 않았기 때문이다. 속도 예측도 이번 집계에서는 개선이 없었다.
O10의 ID Switch 0과 실패 5구간, S03의 장기 전경 소실처럼 위치 규칙만으로 복구할 수 없는 사례가 남는다.
**위치만으로는 객체를 안정적으로 구분할 수 없다.** 단, 잠정 집계의 1–2회 차이를 일반적인 알고리즘 우열로 확대 해석하지 않는다.

## 9. Hand-crafted Feature의 한계

ORB는 국소 코너·방향 및 이진 기술자를 이용하지만, 이번 등록 이미지는 확대된 좁은 사람 crop에서 특징점이 14개뿐이었다.
실제 전체 장면에서는 574–763개가 추출되어도 등록 특징과 ratio test를 통과하는 대응은 전 조건 0개였다.
장면 특징점 수가 많다는 것이 대상 특징이 풍부하거나 올바르게 대응된다는 뜻은 아니다.

회전·자세·시점 변화는 표면의 보이는 부분과 투영을 바꾸고, 가림은 대응될 특징 자체를 제거한다.
ORB의 방향 보정이 이런 비평면 외형 변화나 낮은 해상도의 정보 부족을 모두 보상하지는 못한다.
특히 등록 crop 확대와 전체 프레임의 작은 대상 사이 스케일·해상도 차이도 이번 실패에 영향을 줄 수 있다.

다만 정면부터 전부 0이므로, 이번 결과로 “약 60도가 약 30도보다 얼마나 나쁘다” 또는 “50% 가림이 30%보다 더 나쁘다”라는 경향을 수치적으로 입증할 수 없다.
조건별 매칭/inlier 변화는 **모두 0으로 측정되어 구분되지 않았다**고 보고해야 한다.
모든 `found=False`는 그대로 표시하며 성공 사례를 만들기 위해 등록 이미지·threshold를 바꾸지 않았다.

여기서 hand-crafted의 한계는 사람 정체성·자세 변화를 이 과제 데이터에서 학습하지 않는다는 뜻이다.
ORB의 모든 설계 요소에 통계적 선택이 전혀 없다는 뜻으로 “학습되지 않음”을 과장하지 않는다.
고정된 국소 기술자만으로는 여러 자세의 같은 사람이라는 의미적 공통성을 직접 표현하기 어렵다.

## 10. 딥러닝이 필요한 이유 — 결과에서 출발한 개선 가설

1. **객체의 외형을 학습하면 겹침 문제가 해결될까?** O01처럼 거리 규칙이 다른 사람에게 ID를 넘기는 경우 appearance embedding과 re-identification은 위치 이외의 정체성 단서를 제공한다. 검출 모델이 합쳐진 전경 안에서 각 사람을 찾아내면 관측 수도 보완할 수 있다. 그러나 완전 가림·같은 옷·저해상도에서는 외형도 구분되지 않으므로 완전 해결은 보장되지 않는다.
2. **다양한 변형을 학습하면 특징점 매칭이 개선될까?** 현재 다섯 ORB 조건은 모두 실패했다. 다양한 자세·시점·가림을 학습한 특징이나 객체 검출은 국소 코너 대응이 없어도 대상 범주·외형을 표현할 가능성이 있다. 원영상에서 사라진 디테일이나 완전히 가려진 물체를 확정적으로 복원할 수는 없다. 이번 작업은 딥러닝 비교 실험을 실행하지 않았으므로 성능 향상 수치를 주장하지 않는다.
3. **환경 변화를 학습하면 배경 모델링이 강건해질까?** 17번의 밝기 변화·그림자·정지 사람 사례에서, 다양한 조명의 사람을 학습한 검출기는 시간적 픽셀 변화와 별개로 의미 정보를 제공할 수 있다. 조명 증강, 학습 기반 분할·검출, 외형+운동 추적의 결합이 개선 방향이다. 학습 분포 밖의 극단적 노출·새 카메라·가림에 대한 실패와 데이터·연산 비용은 여전히 남는다.

## 11. 재현과 검증

저장소 루트에서 실행한다. 새 외부 Python 의존성은 추가하지 않았다.

```bash
python scripts/01_setup_data.py --purpose tracker --raw
python scripts/evaluate.py tracker --measure
python scripts/evaluate.py matcher
```

첫 명령은 기존 앱 클래스로 전체 프레임 특징점·17번 학습률·추적 규칙 비교를 다시 실행한다.
학습률 픽셀 비교에는 로컬 LASIESTA `data/tracker/raw/lasiesta/I_IL_02-GT`가 필요하다. 원본 주석 복원은 `scripts/01_setup_data.py --purpose tracker --raw` 절차를 따른다.
추적 집계는 보존된 `ground_truth.json`과 `events.json`을 이용하므로 raw 주석 없이도 재집계할 수 있다.
`scripts/02_prepare_evaluation.py`는 raw 주석이 모두 있으면 bbox를 `data/tracker/generated/annotations/`에 재구성해 보존된 기준과 비교한다. 14번 수동 기준점은 유지한다.
사건 조건 수정 후에는 집계·검토 이미지를 다시 만들고 이 보고서의 표도 새 집계와 맞춰야 한다. `event_log.csv`는 집계 명령이 함께 갱신한다.

검증: 5프레임 ID 확정과 10프레임 연속 누락의 경계, 가림에 의한 연속 구간 단절, 일대일 GT 배정,
저장된 ORB 결과와 앱 직접 호출의 일치, 원본 사건에서 요약표를 역산하는 신규 테스트 **12개 통과**, 기존 테스트를 포함한 전체 **34개 통과**.
이 테스트는 코드의 집계 규칙을 검증하며, 가림 주석의 정답성이나 사람이 ID를 올바르게 판독했음을 증명하지 않는다.
GUI 키보드·웹캠 동작을 이번에 새로 수동 검증하지 않았고 관련 앱 코드는 그대로 보존했다.
