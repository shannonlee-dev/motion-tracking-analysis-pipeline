# 동작 추적·특징점 매칭 실험 보고서

고정 카메라 영상에서 MOG2로 움직임을 검출하고, 중심점 거리로 객체 ID를 연결하며, 등록 이미지의 특징점으로 대상을 찾았다. 실험 결과 **겹침에는 정체성 단서가, 정지·조명 변화에는 움직임과 독립적인 객체 검출이 필요했다.**

## 1. 구현 구조와 설정

`app.py → cli.main() → runner.run()`으로 실행한다. 메인 루프는 영상 읽기·처리 순서·화면·저장을 담당하고, 프레임 분석과 상태 관리는 다음 모듈에 분리했다.

| 모듈·코드 지점 | 역할과 분리 기준 |
| --- | --- |
| [motion.py · MotionDetector.detect](../motion_tracking/motion.py) | MOG2 배경 갱신 → 그림자 제거 → 열림·닫힘 → contour 면적 필터 → bbox 반환. 배경 모델과 전경 처리는 같은 상태·입출력을 공유하므로 한 모듈로 묶었다. |
| [tracker.py · Tracker.update](../motion_tracking/tracker.py) | bbox만 받아 ID·중심·궤적·missing을 관리한다. 영상·GUI에 의존하지 않아 검출기를 교체하거나 별도로 시험할 수 있다. |
| [matching.py · TargetMatcher.match](../motion_tracking/matching.py), [features.py](../motion_tracking/features.py) | 등록 영상 특징과 현재 프레임의 대응·기하 검증을 담당한다. 공통 ratio test·중복 제거는 재사용 함수로 분리했다. 현재 앱은 SIFT/L2이며, 아래 ORB/Hamming 표는 과거 실험이다. |
| [runner.py · run](../motion_tracking/runner.py), [display.py](../motion_tracking/display.py) | 루프에서 `detect(frame) → update(boxes)`와 선택적 `match(frame)`을 호출한다. 화면·키보드 처리는 display에, 입출력 수명과 CSV·영상 저장은 runner에 둔다. |
| [config.py · Config](../motion_tracking/config.py), [cli.py](../motion_tracking/cli.py) | 불변 dataclass에 기본값·범위 검증을 모으고 CLI로 실행별 값을 덮어쓴다. 매직 넘버 분산과 모듈별 설정 불일치를 줄인다. 특징점·기하 검증 상수는 features/matching, 입출력 상수는 constants에 둔다. |

기본값은 `learning_rate=0.01`, `min_area=80`, `kernel_size=3`, `max_distance=50`, `max_missing=15`다. MOG2는 history=500, varThreshold=16, 그림자 검출을 사용한다. 라벨 >200만 전경으로 남기고, contour 면적은 80 이상·전체 화면의 50% 이하만 허용한다. 처음 25프레임은 배경 적응을 위해 bbox를 출력하지 않는다.

새 영상·환경은 소스 수정 없이 `--source`, `--target`과 CLI 설정을 바꾼다. 공통 기본값 변경은 `Config`, 새 검출 방식은 `MotionDetector`, ID 연결 방식은 `Tracker`를 수정한다. 새 영상을 정량 평가하려면 입력 외에 `data/tracker/reference/events.json`과 `ground_truth.json`에도 관찰창·정답을 추가해야 한다.

```bash
python app.py --source data/tracker/inputs/11.mp4 --show-mask
python app.py --source data/tracker/inputs/17.mp4 --learning-rate 0.001 --min-area 80 --kernel-size 3 --max-distance 50 --max-missing 15
```

## 2. 추적 성능과 ID Switch

### 측정 기준

프레임은 0부터 시작하고 구간 양 끝을 포함한다. 이동 10회·겹침 10회·정지 5회·조명 5회의 관찰창을 사용했다. 평가는 GT와 현재 관측 트랙(`missing==0`)을 IoU가 큰 순서로 일대일 대응시키며 IoU ≥0.1만 인정한다. 이는 앱의 거리 기반 연결과 별개다.

- **ID Switch:** 겹침 전 5프레임 이상 확정된 ID가 겹침 후 다른 ID로 5프레임 연속 대응될 때 1회. 이후 추가 변경과 ID 재발급도 포함한다. 겹침 외 조건은 집계 대상이 아니다.
- **추적 실패:** 대상이 존재하지만 대응 ID가 없는 10프레임 이상 연속 구간당 1회.
- **실패율:** 실패가 1회 이상인 사건 수 ÷ 조건별 사건 수 ×100. ID Switch만 발생한 사건은 분자에 넣지 않는다.
- warmup·GT 부재·가림 제외 후보는 연속 구간을 끊는다. 마지막 확정 ID는 유지한다.

### 추적 성능 표 — 기존 잠정 결과 보존

| 상황 | 테스트 횟수 | ID Switch | 추적 실패 | 실패율 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 단일 객체 이동 | 10 | 해당 없음 | 7 | 30.0% | 실패 사건 3/10; 미확정 대응·가림 조건 적용 |
| 두 객체 겹침 | 10 | 15 | 39 | 100.0% | 실패 사건 10/10; 미확정 대응·가림 조건 적용 |
| 객체 일시 정지 | 5 | 해당 없음 | 3 | 60.0% | 실패 사건 3/5; 미확정 대응·가림 조건 적용 |
| 조명 변화 | 5 | 해당 없음 | 3 | 40.0% | 실패 사건 2/5; 미확정 대응·가림 조건 적용 |

표의 출처는 [고정 요약 CSV](evidence/tracking/tracking_summary.csv)다. 작은 신체 bbox의 IoU 부족, 14번의 수동 보간 GT, 04–11번의 미확정 가림 제외 때문에 **잠정 자동 대조 결과**로 해석한다. 실제 신체 50% 가림을 대상별로 확정하지 않았고 두 사람을 함께 제외한 구간이 있다. [사건별 로그](evidence/tracking/event_log.csv)의 겹침 합계는 ID Switch 15회·실패 39구간으로 표와 일치한다. 최종 성능 확정에는 대상별 가림 제외와 자동 대응의 정확성을 검토해야 한다.

### 거리 연결과 실패 원인

`Tracker.update`는 기존 중심 `positions`와 현재 bbox 중심 `centers`의 모든 쌍에 대해 다음 거리를 계산한다.

```python
distances = np.linalg.norm(
    np.array(positions)[:, None, :] - centers[None, :, :], axis=2
)
```

`np.argsort(distances, axis=None, kind="stable")`로 가까운 쌍부터 방문하고, 아직 사용하지 않은 트랙·검출만 연결한다. `max_distance` 초과 쌍은 배제한다. 전체 비용을 최적화하는 배정이 아닌 탐욕적 일대일 매칭이다.

연결된 트랙은 bbox·중심·궤적을 갱신하고 missing을 0으로 만든다. 연결되지 않은 기존 트랙은 missing을 증가시키고 **15를 초과할 때 삭제**한다. 연결되지 않은 검출은 새 ID를 받는다. 거리 제한은 멀리 떨어진 물체의 오연결을 막고, 유예 프레임은 짧은 검출 공백을 견디기 위한 기준이다. 25 fps에서 기본 유예는 약 0.6초지만, 오래 보관할수록 다른 사람이 옛 ID를 이어받을 위험도 커진다.

겹침에서는 두 사람이 한 contour로 합쳐져 관측이 하나가 되거나, 다른 사람의 중심이 더 가까워진다. 분리 후 중심만으로 원래 사람을 판별할 정보가 없다. **11.mp4의 73–77프레임(약 2.92–3.08초)**에서는 교차 후 ID 1→4, ID 4→3 변경이 확인된다([관찰 이미지](evidence/tracking/review/O09.jpg)). 19번 정지 사건에서는 사람이 남아 있어도 178–270프레임 동안 대응이 사라졌다. ID Switch가 0이어도 검출 누락이 있으면 추적 성공은 아니다.

과거 동일 검출에 대한 규칙 비교는 다음과 같다. 현재 앱에는 속도 예측 옵션이 없다.

| 추적 규칙 | 겹침 후 ID Switch | 겹침 추적 실패 | 겹침 실패율 |
| --- | --- | --- | --- |
| 기본 거리50 / missing15 / 예측OFF | 15 | 39 | 100.0% |
| 거리80만 변경 | 17 | 39 | 100.0% |
| missing30만 변경 | 14 | 39 | 100.0% |
| 속도 예측ON만 변경 | 15 | 39 | 100.0% |

거리를 넓히면 ID 변경이 15→17회로 증가했고, missing을 늘려도 15→14회에 그쳤으며 누락 39구간은 그대로였다. 위치 규칙은 사라진 관측이나 외형 정보를 만들어내지 못한다. 이 비교 역시 위 고정 요약과 같은 잠정 기준이며, 작은 차이를 일반적인 알고리즘 우열로 해석하지 않는다.

## 3. 학습률과 모폴로지 실험

### 학습률: 정지 객체 보존과 조명 적응의 충돌

17번 영상 525프레임을 학습률마다 새 MOG2로 처음부터 처리했다. LASIESTA GT의 사람 픽셀을 기준으로 구간별 TP·FP를 합산했다. 전경 recall은 TP/사람 픽셀, 배경 오검출률은 FP/배경 픽셀이며 추적 실패율과 다르다.

| 학습률 | 접근 80–169 전경 recall | 위치 정지 177–256 전경 recall | 조명 205–249 배경 오검출률 | 복귀 270–379 전경 recall |
| --- | --- | --- | --- | --- |
| 0.001 | 90.94% | 97.43% | 53.82% | 80.38% |
| 0.01 | 66.01% | 26.19% | 14.35% | 59.24% |
| 0.1 | 0.02% | 0.00% | 0.01% | 0.08% |

- **0.001:** 정지 사람 recall 97.43%로 신체를 오래 보존하지만, 조명 변화의 배경 오검출률이 53.82%다. f240 부근 창·벽까지 전경이 되어 사람과 합쳐지거나 면적 필터에서 탈락할 수 있다.
- **0.01:** 정지 recall이 26.19%로 떨어지고 f240에는 사람의 작은 조각만 남는다. 조명 오검출은 14.35%로 줄지만 정지와 조명 모두를 안정적으로 처리하지 못했다.
- **0.1:** 정지 recall 0%, 이동 중인 접근 구간도 0.02%다. 정지 구간 사람 픽셀의 90.15%가 MOG2 원시 배경 라벨, 9.73%가 그림자로 분류되어 후속 전경 처리에서 사라졌다.

MOG2는 위치별 픽셀 분포를 갱신하므로 큰 학습률은 새 관측을 빠르게 배경으로 흡수하고 작은 학습률은 오래된 배경을 유지한다. 정지한 사람도 배경이 되고, 바뀐 조명도 움직임이 된다. 이번 결과에서 하나의 학습률로 두 문제를 동시에 해결하지 못했다. [측정 CSV](evidence/learning-rate/learning_rate_summary.csv)에 구간과 원시 라벨 비율을 보존했다.

### 모폴로지: 잡음 제거와 작은 객체 손실

열림(침식→팽창)은 작은 전경 잡음을 지우고, 닫힘(팽창→침식)은 전경 내부의 작은 구멍과 틈을 메운다. 커널이 커지면 작은 신체 부분도 지우거나 가까운 영역을 연결할 수 있다.

추가로 11번 영상을 각 커널마다 새 모델로 처음부터 처리하고, 다른 기본값을 고정해 f25–149의 125프레임을 비교했다. 1×1은 모폴로지에 의한 변화가 없는 기준이다.

| 타원 커널 | 평균 전경 픽셀 수 | 프레임당 평균 검출 bbox | bbox 없는 프레임 |
| --- | ---: | ---: | ---: |
| 1×1 | 1,574.54 | 2.000 | 0 |
| 3×3 | 1,290.57 | 1.976 | 0 |
| 5×5 | 1,061.85 | 1.824 | 1 |

이 영상에서는 큰 커널일수록 전경과 bbox가 줄고 5×5에서 검출 공백도 생겼다. 전경 감소에는 잡음과 신체 손실이 함께 포함될 수 있어 정확도 개선으로 단정하지 않는다. 기본 3×3은 작은 영역을 정리하는 출발점이며, 대상이 작아지는 새 환경에서는 커널·면적 임계값을 함께 재평가한다. [추가 실험 설정·결과](evidence/morphology/comparison.json)에 입력 해시와 집계 방법을 기록했다.

## 4. 특징점 매칭 성능과 개선 시도

### 전체 프레임 ORB 성능표 — 기존 결과 보존

과거 ORB 앱에 Jogging 전체 프레임을 입력했다. 등록 특징점은 14개, ORB nfeatures=1500, Hamming kNN=2, ratio <0.75를 사용했다. 중복 대응을 제거한 매칭 수/14×100이 매칭률이다. 인식은 RANSAC(3픽셀), inlier 8개 이상·비율 0.5 이상 및 사각형 기하 조건으로 판정했다.

| 조건 | 전체 프레임 추출 특징점 수 | 매칭된 특징점 수 | 매칭률 | RANSAC Inlier 수 | TARGET DETECTED 여부 |
| --- | --- | --- | --- | --- | --- |
| 정면 | 686 | 0 | 0.00% | 0 | 아니요 |
| 약 30도 회전 | 632 | 0 | 0.00% | 0 | 아니요 |
| 약 60도 회전 | 763 | 0 | 0.00% | 0 | 아니요 |
| 약 30% 가림 | 757 | 0 | 0.00% | 0 | 아니요 |
| 약 50% 가림 | 574 | 0 | 0.00% | 0 | 아니요 |

[원본 측정 CSV](evidence/matching/features.csv). 원본 JPG 33·140·300·65·68번(앱 프레임 32·139·299·64·67)을 사용했다. 각 조건은 1프레임이며 각도·가림률은 육안 근사다. 정면부터 모두 0이므로 이 표만으로 회전·가림에 따른 감소 추세를 입증할 수 없다. 현재 SIFT 앱의 결과로도 해석하지 않는다.

### 개선 시도: 그레이스케일·확대·SIFT 비교

대상 위치를 아는 GT crop에서 ORB와 SIFT를 비교했다. 등록 crop은 25×101픽셀이다. 원본 BGR, 원본 그레이스케일, 그레이스케일·4배 확대를 등록·평가 양쪽에 동일하게 적용했다. 두 알고리즘 모두 nfeatures=1500, kNN=2, ratio <0.75와 등록 특징점 중복 제거를 사용했다. 아래는 전체 프레임 인식과 별개인 ROI 실험이다.

| 알고리즘 | 등록 특징점: 원본 BGR | 등록 특징점: 원본 그레이스케일 | 등록 특징점: 그레이스케일·4배 확대 |
| --- | ---: | ---: | ---: |
| ORB | 0 | 0 | 14 |
| SIFT | 24 | 24 | 100 |

| 알고리즘 | 조건 (원본 프레임) | 조건 특징점 수: 원본→확대 | 대응점 수: 원본→확대 | 매칭률: 원본→확대 |
| --- | --- | ---: | ---: | ---: |
| ORB | 정면 (33) | 0→24 | 0→0 | N/A→0.00% |
| ORB | 약 30° 방향 변화 (140) | 0→10 | 0→0 | N/A→0.00% |
| ORB | 약 60° 방향 변화 (300) | 0→20 | 0→0 | N/A→0.00% |
| ORB | 약 30% 가림 (65) | 0→14 | 0→1 | N/A→7.14% |
| ORB | 약 50% 가림 (68) | 0→6 | 0→1 | N/A→7.14% |
| SIFT | 정면 (33) | 24→90 | 3→9 | 12.50%→9.00% |
| SIFT | 약 30° 방향 변화 (140) | 31→81 | 2→4 | 8.33%→4.00% |
| SIFT | 약 60° 방향 변화 (300) | 46→84 | 1→4 | 4.17%→4.00% |
| SIFT | 약 30% 가림 (65) | 21→66 | 1→2 | 4.17%→2.00% |
| SIFT | 약 50% 가림 (68) | 22→54 | 0→0 | 0.00%→0.00% |

원본 BGR와 그레이스케일의 다섯 조건 결과는 같아 명시적 회색조 변환만의 개선은 없었다. ORB는 원본 등록 특징점이 0개여서 매칭률이 N/A다. 폭 25픽셀의 작은 crop을 확대하자 등록 특징점 14개와 가림 조건별 대응 1개를 얻었지만 개선은 제한적이었다.

SIFT 확대 후 대응점 합계는 **7→19개**, 방향 변화·가림 네 조건만의 합계는 **4→10개**로 늘었다. 다만 등록 특징점도 24→100개로 늘어 평균 매칭률은 **5.83%→3.80%**로 낮아졌고, 50% 가림은 여전히 대응 0개였다. 확대는 대응점 확보에 도움을 주었지만 사라진 영상 정보를 복원하지는 않는다. ROI 대응의 기하 검증·오검출 평가는 하지 않았으므로 인식 정확도 향상으로 해석하지 않는다. [30개 측정 결과](evidence/matching-preprocessing/metrics.csv), [설정](evidence/matching-preprocessing/metadata.json).

회전 보정이 있는 특징점도 사람의 비평면 자세·시점 변화로 달라진 표면을 완전히 대응시키지 못한다. 가림은 대응할 표면 자체를 없앤다. 원본 SIFT의 정면 3개, 방향 변화 2·1개, 가림 1·0개와 확대 후에도 남는 실패는 국소 수작업 특징만으로 사람 정체성을 유지하기 어렵다는 근거다.

## 5. CCTV 적용과 결론

이번 시험에서 가장 먼저 대비할 조건은 **출입구의 보행자 교차·가림**이다. 겹침 10개 사건 모두 추적 실패가 있었고, 거리·유예시간 조정으로 해결되지 않았다. 실제 현장의 실패 순서는 혼잡도와 조명에 따라 달라질 수 있다. 겹침 구간은 ID 불확실 상태로 표시하고, 단일 프레임의 ID 변경을 곧바로 경보로 사용하지 않으며, 원영상과 로그를 함께 보존하겠다. 정지자를 놓치는 배경 차분만으로 보안 대상의 부재를 판단해서도 안 된다.

| 확인된 한계 | 딥러닝을 도입할 이유와 대응 방향 |
| --- | --- |
| 겹침 후 ID 변경, 위치 규칙 개선 한계 | 사람 검출기로 개별 관측을 확보하고, 외형 임베딩·Re-ID를 운동 정보와 결합해 겹침 전후 정체성 단서를 보충한다. |
| 정지 사람 소실과 조명 오검출의 상충 | 정지 여부와 독립적으로 사람을 검출하고, 현장 조명·그림자·노출 변화를 포함한 데이터와 증강으로 환경 변화에 대응한다. |
| ORB 전 조건 실패, SIFT 확대 후에도 가림 실패 | 여러 자세·시점·부분 가림에서 같은 대상을 표현하도록 데이터 기반 특징을 학습한다. |

고전적 방식은 계산 과정이 명확하고 CPU에서 구현하기 쉽지만, 픽셀 변화·중심 거리·국소 특징만으로는 이 실험의 정체성·정지·가림 문제를 함께 해결하지 못했다. 딥러닝은 부족한 의미·외형 단서를 추가하기 위한 다음 단계다. 이번에 딥러닝 비교 실험은 하지 않았으므로 향상 수치는 주장하지 않는다. 도입 후에는 같은 사건창과 새 카메라 영상에서 ID Switch·조건별 실패율·오경보·처리 지연을 다시 평가해야 한다.

보존 표의 기준은 2026-09-18–19, 코드 `a48a5515d2dd94ec442d9d02f2495f541dac5b84`, Python 3.12.3/OpenCV 4.13.0/NumPy 2.4.3, Linux/WSL2 CPU, 스레드 1·seed 0이다([환경 기록](evidence/tracking/environment.json)). 추가 커널 비교는 2026-09-20의 현재 코드로 별도 수행했다. `docs/evidence/`는 고정 기록이고 현재 실행 결과는 `results/`에 저장한다.
